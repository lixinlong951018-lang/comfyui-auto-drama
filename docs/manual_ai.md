# 手动 AI / API 调用

设置 → 语言模型「调用方式」与文生图模型「调用方式」分别选 **手动调用 AI** 或 **API 自动调用**，再保存配置。默认 API，不改变原配置。两项可混用。

原制作步骤保持不变。手动请求出现后，一键复制完整内容，交给网页 AI；文本粘贴原始回答，图片上传 PNG/JPEG/WebP（≤16MB），点击继续。系统继续原解析、质检、保存和后续调用。语言模型手动模式也包含原视觉质检调用，届时会显示实际图片，点击图片可下载参考。

## 接入位置

- 所有业务语言调用仍经过 `lmstudio_chat`：剧本生成、改写、片段转换、批量分镜扩写、逐段扩写、提示词润色、图片提示词修改、分镜图片提示词生成。
- 所有生图仍经过 `boogu_generate`：本地 Boogu、OpenAI 兼容与 DashScope。
- 各适配器组装完原 `urllib.request.Request` 后，统一经过 `_ai_open` → `ai_bridge.open_request`。API 发送原请求，手动保存同一个实际 JSON 请求并等待返回。OpenAI / Claude / DashScope 的原解析器继续处理返回。
- `vision_ask` 使用相同出口。质检提示词和图像仍由原函数组装，没有更换规则或绕过质检。
- 界面按实际角色顺序展示系统、用户及其他消息，并附完整原请求 JSON，包含模型、参数和格式要求；认证密钥不属于提示词，不展示。
- **现有三个生图适配器只发送文本，未提交参考图片**。因此生图面板如实显示“本次原接口请求未携带参考图”；没有把已有角色图虚构成原请求参考。视觉质检请求实际包含图片，面板按原数据展示。

## 恢复与对应关系

`console.db` 新增独立 `ai_jobs` / `ai_calls` 调用日志表。原项目、剧本、分镜、视频任务数据结构不变。

- 操作绑定发起时的项目、输入和配置；每次调用绑定操作编号、调用序号及独立请求编号。
- 请求入队前复用原项目保存函数，先持久化最新页面上下文。
- 待处理请求、返回内容和已完成解析结果持久化。正常关闭时等待中的调用暂停，启动后从日志恢复；已返回的调用复用原记录，未完成的调用显示原请求编号和原完整内容。
- 正式返回后的项目保存与操作完成标记在同一 SQLite 事务中提交。相同请求双击提交为幂等操作；不同操作/请求编号或覆盖已提交结果会报错。
- 切换项目后结果仍保存到原项目，避免写入当前其他项目；切换调用模式不会丢弃已等待的请求。已创建操作使用发起时配置，新操作使用最新配置。
- 手动逐段扩写继续运行原逐段工作函数，每段仍即时保存；API 扩写保留原异步任务编号和进度查询。
- 原页面回调继续执行，不重新设计步骤。在同一浏览器中，原素材单张/四视图/全部生成的继续位置以本地存储书签恢复，已生成图从原素材映射判断并跳过；待处理 AI 请求本身存于 SQLite。
- 关闭网页不停止服务。Windows 两个启停入口、ComfyUI 独立运行、H3 工作流、尾帧函数及链式生成逻辑保持不变。
